# 错误引用率基线报告（v0.2 · 构造评测）

> **重要声明：本基线是构造评测（constructed evaluation），不含任何模型生成环节。**
> 全部 550 条测试答案由确定性规则从真实语料构造而成，测的是 guard 本身的
> 检出率（fabricated / misquoted / uncited 三组）与误报率（grounded 组），
> 不是「模型生成答案中的错误引用率」。全程无模型判断，所有比对均为确定性字符串运算。

## Abstract (English)

This baseline is a **constructed evaluation with no model in the loop**: all 550 test answers
are generated by deterministic rules from statute-rag's real corpus (14,212 articles, 238 laws
and judicial interpretations), so it measures the guard's own detection rate (fabricated /
misquoted / uncited groups) and false-positive rate (grounded group) — not the wrong-citation
rate of model-generated answers. Results with a fixed seed (20260928): grounded FP 0.0%
(0/250), fabricated detection 100.0% (120/120), misquoted detection 100.0% (120/120),
uncited detection 100.0% (60/60). Running the evaluation surfaced a real guard bug — the
index silently kept only the last text when the corpus contained duplicate (law, article no.)
keys, making verdicts depend on JSONL line order; 5 verbatim quotes were falsely flagged.
After the fix (all variants retained; a quote passing against any variant counts as faithful),
FP dropped from 2.0% to 0.0% with detection rates unchanged. See "误报分析与 guard 修复" below.

## 一、数据与方法

**语料**：[statute-rag](https://github.com/1438388098-glitch/statute-rag) 公开仓导出的真实法条
语料 `corpus.jsonl`，14,212 条、238 部法律法规及司法解释。**只读引用，不复制进本仓库**；
脚本以 `--corpus` 参数指向该路径，汇总产物不含条文全文。

**构造规则**（全部确定性，固定随机种子 `--seed 20260928` 从语料中抽样）：

| 组 | n | 构造规则 | 期望结果 | 测什么 |
|---|---|---|---|---|
| grounded | 250 | 引文 = 该条文开头逐字片段（≤80 字，句号处截断）；引用 = 该条文的正确 Citation：`【法名 第X条｜引文】`；句尾接无断言词的中性陈述 | 0 命中 | 误报率 FP rate |
| fabricated | 120 | 同上，但条号改为 `第九千零一条` 起的编号（9001+，远超语料中任何一部法律的条数，构造时断言该键不在索引中），引文仍为逐字片段 | 触发 FABRICATED_CITATION | 检出率 |
| misquoted | 120 | 引文做系统性改写，三种策略按序尝试：① 数字替换（中文/阿拉伯数字轮换一位）；② 同义词替换（应当→必须、不得→禁止、可以→能够 等）；③ 拼接两条不同条文（前半句取本条、后半句取同法另一条） | 触发 MISQUOTED_TEXT | 检出率 |
| uncited | 60 | 取真实条文中含断言词（应当/不得/有权/构成/无效/视为/负责/承担）的整句，冠以「法律意见：」、不带任何引用标记 | 触发 UNCITED_CLAIM | 检出率 |

构造合法性由脚本自行保证（不依赖 guard 结果筛选，grounded 组尤其不筛——否则会把真误报藏起来）：

- grounded 的引文取自条文原文的连续切片，按 guard 同样的去空白比对必然是子串；
- misquoted 的每种改写候选都经验证「确非该条文去空白子串」才采纳，保证每条样本的缺陷真实存在（本组实测三种策略分布：数字替换 41 / 同义词替换 41 / 拼接 38，0 条跳过）；
- uncited 的句子构造时断言 `CLAIM_PAT` 命中，保证断言词表内。

## 二、结果（guard 修复后，seed=20260928）

| 组别 | n | 触发数 | 比率 | 预期规则命中 | 预期外规则 |
|---|---|---|---|---|---|
| grounded | 250 | 0 | **FP 0.0%** | — | 0 |
| fabricated | 120 | 120 | **检出 100.0%** | 120/120 | 0 |
| misquoted | 120 | 120 | **检出 100.0%** | 120/120 | 0 |
| uncited | 60 | 60 | **检出 100.0%** | 60/60 | 0 |

- 整体：550 条构造答案，触发 300 条；构造语料错误引用率 54.5%（按设计，缺陷组占主导，此数字无独立含义）。
- 各组只命中各自的预期规则，无串扰（fabricated 组因存在性校验短路，不再重复计引文失真，与设计一致）。
- 汇总明细：[`docs/baseline-metrics.json`](./baseline-metrics.json)。

## 三、误报分析与 guard 修复（before / after）

**首轮实跑 grounded 组出现 5 条误报（FP 2.0%），全部为 MISQUOTED_TEXT**，涉及条文：

1. 烈士褒扬条例 第二十二条
2. 烈士褒扬条例 第三十一条
3. 烈士褒扬条例 第七条
4. 中华人民共和国企业所得税法实施条例 第九十一条
5. 中华人民共和国药品管理法实施条例 第四十六条

**根因**：这 5 条的引文都是条文原文的逐字片段，不可能失真。排查发现语料中同一
（法名，条号）存在重复条目——全库 401 组重复键，其中 396 组文本不同（同一法律的
历次修订快照并存）。而 `build_index` 用字典推导式建索引，重复键**后者静默覆盖前者**：
引文来自 A 版本文本，索引里却只留了 B 版本，逐字比对必然失败。更糟的是判定结果
依赖 JSONL 行序，同一个答案换个语料导出顺序结论就会翻转。

**修复**（`legal_hallu_guard/guard.py`）：

- `build_index`：重复键的全部版本文本保留为列表；
- 引文保真：与**任一**版本逐字一致即算保真（确定性、与行序无关）；
- 新增回归测试 `test_duplicate_article_keys_keep_all_variants` 锁定该行为。

| 指标 | 修复前 | 修复后 |
|---|---|---|
| grounded FP | 2.0%（5/250） | **0.0%（0/250）** |
| fabricated / misquoted / uncited 检出率 | 100% / 100% / 100% | 100% / 100% / 100%（不变） |
| 单元测试 | 8 例全绿 | 9 例全绿（8 例零回归 + 1 例新增） |

这是本评测的直接产出之一：基线流程在真实语料上第一轮就抓到了 guard 自身的判定 bug。

## 四、与 v0.1 虚构案例自检的关系

v0.1 的 4 条虚构案例（good / fabricated / misquote / uncited）是**手写的最小冒烟自检**，
只验证三类规则「各能命中一次」，不产生任何比率。本基线把同一套规则放到真实语料的
**550 条**构造样本上规模化验证，并新增了 v0.1 没有的两个维度：

- **误报率**：250 条「应该放行」的样本，测 guard 会不会冤枉正确引用（结果抓出并修掉了重复条号 bug）；
- **端到端贯通**：真实法条的长文本、真实法名长度、真实条号书写（如「第九百零一条」级中文数字）下的正则解析、索引查找、去空白归一化全链路。

虚构案例保留不变，继续作为最快冒烟检查；本基线是它的规模化续篇。

## 五、复现

```bash
# 默认语料路径 + 默认种子（20260928），输出与报告完全一致
py -3.13 scripts/run_baseline_eval.py --out docs/baseline-metrics.json

# 自备语料 / 换种子 / 调组大小
py -3.13 scripts/run_baseline_eval.py --corpus <corpus.jsonl> --seed 123 \
    --grounded 250 --fabricated 120 --misquoted 120 --uncited 60

# 单元测试（9 例，含重复条号回归测试）
py -3.13 -m unittest discover -s tests -v
```

脚本仅用 Python 标准库；语料路径参数化，可指向任何 statute-rag 导出格式的 JSONL。

## 六、边界声明

1. **不测模型**：本基线不含任何模型生成环节。全部答案为确定性规则构造，数字反映
   guard 的检出/误报能力，**不能**解读为「某模型在法律问答中的错误引用率」。
   对真实模型输出的评测属于 roadmap v0.2 的后续工作（需要模型 API）。
2. **misquoted 检出 100% 是构造使然**：每条改写样本在构造时已验证「确非原文子串」，
   而引文保真规则正是子串比对——因此 100% 验证的是管线端到端贯通（解析/索引/归一化/
   规则触发），不是模型级的改写识别力。
3. **已知盲区**：未标记的省略式截断（引文是原文的连续子串，但断章取义）不违反子串
   性质，MISQUOTED_TEXT 抓不到；引用版本选择（语料中同一条号多个修订版本并存时，
   答案引的是否为现行有效版本）也超出 v0.2 确定性校验的范围。
4. **uncited 检出 100% 局限于 v0.1 封闭断言词表**（应当/不得/有权/构成/无效/视为/负责/承担）；
   构造时要求句子命中词表，词表外的断言表述不在本评测范围内。
5. **语料来源**：statute-rag 公开仓，14,212 条真实法条；本仓库只读引用其路径，
   不复制、不再分发语料内容，汇总 JSON 仅含法名/条号/判定消息。
